## Описание проекта
Многостраничный сайт магазина настольных игр. Основа взята из HTML/CSS-проекта КР №1 (тот же магазин, те же страницы), Bootstrap и другие CSS-фреймворки не используются.
В этой работе сайт адаптирован под экраны от 360 до 1440 px и проверен на доступность. Страниц пять: главная, каталог, страница товара, форма заявки и контакты.

## Структура проекта
```
kr3-responsive-shop/
├── index.html
├── catalog.html
├── product.html
├── order.html
├── contacts.html
├── css/
│   ├── style.css          базовые стили (мобильная версия)
│   └── responsive.css     адаптивные правила (только min-width)
├── js/
│   ├── main.js            меню, окно, фильтр, формы
│   └── products.js        данные товаров
├── images/                картинки в PNG и WebP, по 3 размера на товар
├── lighthouse/            результаты проверки доступности
├── README.md
└── .gitignore
```
На каждой странице сначала подключён `css/style.css`, потом `css/responsive.css`, поэтому адаптивные правила переопределяют базовые. В `<head>` везде есть `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.

## Адаптивные решения
- Подход **Mobile First**: `style.css` описывает мобильную версию, а `responsive.css` расширяет её только через `@media (min-width: ...)`.
- Точки останова в `em`: 30em (480px), 40em (640px), 48em (768px), 64em (1024px), 80em (1280px). Размеры в `em` учитывают увеличенный шрифт в браузере.
- **Навигация** (Flexbox): на телефоне меню спрятано за кнопкой «Меню», с 768px оно становится строкой в шапке.
- **Hero-блок**: на телефоне колонка, с 1024px две колонки (Grid), заголовок растёт по ширинам.
- **Сетка карточек** (Grid): 1 колонка, с 480px две, на главной с 1024px четыре, в каталоге с 1280px три.
- **Каталог и фильтр**: на телефоне фильтр раскрывается кнопкой «Фильтры и сортировка», с 1024px он постоянно виден слева (Grid `16rem + 1fr`, `position: sticky`).
- **Страница товара**: на телефоне картинка над описанием, с 768px две колонки.
- **Форма заявки**: на телефоне одна колонка, с 768px две (Grid), поля высотой не меньше 44px и шрифтом 16px, кнопки на всю ширину.
- **Контакты**: на телефоне блоки друг под другом, с 768px информация и форма рядом.
- **Таблицы**: см. раздел ниже.
- Во всех сетках колонки заданы как `minmax(0, 1fr)`, чтобы длинное содержимое не растягивало страницу вбок. Длинные слова переносятся (`overflow-wrap`).
- Горизонтального скролла всей страницы нет ни на одной ширине. Внутренняя прокрутка допускается только в `.table-wrapper`.

## Responsive images
- Глобальное правило `img, video { max-width: 100%; height: auto; }`.
- У всех `<img>` указаны `width` и `height`, чтобы страница не прыгала при загрузке, у картинок ниже первого экрана `loading="lazy"`.
- Карточки и страница товара: `<picture>` с WebP (`<source type="image/webp">`) и PNG-запасом, у каждого `srcset` с дескрипторами `480w`, `640w`, `960w` и `sizes` под реальную ширину картинки в макете.
- Hero-блок: `<picture>` с **разными картинками для разных экранов** (art direction). На планшете (768-1023px) показывается широкий баннер, на телефоне и desktop картинка 4:3.
- Проверка во вкладке Network: на 360px грузится `p1-480.webp`, hero `hero-narrow-480.webp`, на 768px hero `hero-wide-960.webp`, на 1440px hero `hero-narrow-800.webp`.

## Адаптивная таблица
- **Сравнение игр** (`product.html`): на экранах до 640px каждая строка таблицы превращается в карточку, подписи колонок берутся из `data-label`, заголовок таблицы скрыт визуально, но остаётся для скринридера. С 640px это обычная таблица внутри `.table-wrapper { overflow-x: auto }` с `min-width: 40rem`.
- Чтобы карточный режим не ломал семантику таблицы для скринридеров, у элементов добавлены роли `table`, `rowgroup`, `row`, `columnheader`, `cell`.
- **Характеристики**: таблица из двух колонок помещается на любом экране, обёрнута в `.table-wrapper` на всякий случай.

## Доступность
- Ссылка пропуска «Перейти к основному содержимому» в начале каждой страницы.
- Видимый фокус (`:focus-visible`, контур 3px) на всех интерактивных элементах, на тёмном фоне контур жёлтый.
- На каждой странице один `h1`, заголовки идут по порядку без пропусков уровней.
- Семантика: `header`, `nav` (с `aria-label`), `main`, `aside`, `footer`, `section` с `aria-labelledby`, списки для карточек, `details/summary` для вопросов и ответов.
- У всех полей формы есть `label` (через `for`/`id`), группы переключателей в `fieldset` и `legend`, обязательные поля с `required`, подсказки связаны через `aria-describedby`, подходящие `autocomplete` и `inputmode`.
- У картинок товаров осмысленный `alt` («Коробка настольной игры «Каркассон»»). Декоративный баннер в hero имеет пустой `alt=""`.
- Контраст проверен по формуле WCAG: текст не ниже 4.5:1, границы полей и контуры фокуса не ниже 3:1 (расчёт в `lighthouse/a11y-selfcheck.txt`). Для этого цвет приглушённого текста и бейджей подобран заранее.
- Модальное окно сделано на нативном `<dialog>` с `showModal()`: фокус остаётся внутри окна, закрывается по Esc и кнопкам, после закрытия фокус возвращается на кнопку, из-за которой оно открылось. Есть `aria-labelledby`.
- Мобильное меню: кнопка с `aria-expanded` и `aria-controls`, закрывается по Esc (фокус возвращается на кнопку), по клику вне меню и при переходе на широкий экран.
- Сообщения об успехе и «добавлено в корзину» объявляются скринридером через `role="status"`.
- Учтены `prefers-reduced-motion`, сенсорные экраны (`pointer: coarse`) и печать.

## Проверенные ширины
360px, 430px, 768px, 1024px, 1440px. На каждой проверены шапка, навигация, hero, сетка карточек, каталог и фильтр, страница товара, таблицы, форма заявки, контакты, подвал и модальное окно. Горизонтального скролла нет.



## Самостоятельные доработки
- Улучшенная мобильная навигация: кнопка с состоянием, Esc, клик вне меню, сброс при смене ширины.
- Каталог: раскрывающийся фильтр на телефоне и постоянная боковая панель на desktop, фильтр по категориям и цене, сортировка, сообщение при пустом результате, счётчик.
- Таблица на телефоне превращается в карточки.
- Несколько вариантов изображений: WebP и PNG, три размера, `<picture>` с art direction для hero.
- Доступное модальное окно, skip-link, ARIA только там, где нужно.
- Страница товара собирается по параметру `?id=` из `js/products.js`.
